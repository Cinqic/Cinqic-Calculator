# Cinqic Calculator - Android (Kivy) frontend

A separate, independent frontend from the Tkinter desktop app
(`src/cinqic_calculator/ui/`), built with [Kivy](https://kivy.org). It
reuses the platform-independent core in `src/cinqic_calculator/`
(`calculator.py`, `evaluator.py`, `financial.py`, `conversions.py`,
`history.py`, `settings.py`, `storage.py`, `constants.py`) unchanged.

## This cannot be built on Windows

Building the APK requires `buildozer` / `python-for-android`, which needs
WSL/Linux/macOS, the Android SDK/NDK, and various native toolchains -
none of which are available (or supported) on a plain Windows machine.
Build it on a Linux machine, in a Linux VM/container, or in CI.

## Building the debug APK

1. **Bundle the shared core.** `buildozer.spec`'s `source.dir` is this
   `android/` directory, and buildozer only packages files that live under
   `source.dir`. The shared `cinqic_calculator` package lives outside it,
   at `../src/cinqic_calculator`, so copy (or symlink) it in first:

   ```bash
   cp -r ../src/cinqic_calculator android/cinqic_calculator
   ```

   (Run from the repo root; adjust the path if invoking from elsewhere.)
   `cinqic_calculator` has zero third-party dependencies, so nothing else
   is needed for it to import cleanly once bundled this way.

2. **Install the build tooling** (Linux only):

   ```bash
   pip install -r android/requirements-android.txt
   ```

   `buildozer` will also prompt to install/accept the Android SDK
   licenses and download the NDK on first run.

3. **Build the debug APK:**

   ```bash
   cd android
   buildozer -v android debug
   ```

   The resulting `.apk` is written to `android/bin/`.

## CI

- [`.github/workflows/test-android.yml`](../.github/workflows/test-android.yml)
  runs the desktop+android glue test suite and `ruff`, then builds an
  **unsigned debug APK** on `ubuntu-latest` via Buildozer and inspects its
  package ID/permissions with `scripts/inspect_android_apk.py`. Triggers
  on PRs/pushes touching `android/**` or the shared core, plus manual
  dispatch.
- [`.github/workflows/release-android.yml`](../.github/workflows/release-android.yml)
  builds, signs, zip-aligns, verifies, inspects, checksums, and publishes
  the **release APK** on an `android-v*` tag. It requires these repository
  secrets to exist first: `ANDROID_KEYSTORE_BASE64`,
  `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`
  — without them it fails loudly at the signing step rather than publish
  an unsigned APK.

## What's intentionally out of scope here

- Generating the actual signing keystore and configuring the secrets
  above - that requires a secure, human-in-the-loop step and is not done
  by CI or by an agent.
- `android.permissions` in `buildozer.spec` is intentionally empty - the
  app is fully offline and only touches its own private Kivy
  `user_data_dir`, which needs no permission.

## Layout

```
android/
  main.py                 Kivy App entry point (CinqicCalculatorApp)
  android_constants.py    Android-only version string, privacy/Juniper copy
  logic.py                Pure-Python glue logic (no kivy import) - tested
                           directly by tests/test_android_glue.py
  screens/                One Screen subclass per app screen
  kv/                     One .kv layout file per screen
  buildozer.spec
  requirements-android.txt
  assets/icon/            Launcher/adaptive icon, presplash, and contact
                          sheet - generated by scripts/process_logo.py
                          from the official logo, never hand-edited
```

Imports between `main.py`, `logic.py`, `android_constants.py`, and
`screens/*.py` are flat (e.g. `from logic import ...`), not
`from android.logic import ...`. On-device, python-for-android runs
`main.py` with this directory as the app's root, and Python also puts a
directly-run script's own directory first on `sys.path` - so the same flat
imports work for local desktop iteration too (`python android/main.py`, on
a machine with Kivy installed). Only `tests/test_android_glue.py`, which
runs from the repository root under pytest, addresses this package via the
dotted `android.logic` path.
