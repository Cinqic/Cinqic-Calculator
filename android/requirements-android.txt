# Pinned build-time tooling for building the Android APK in CI
# (GitHub Actions ubuntu-latest). These are the tools that run buildozer /
# python-for-android on the CI runner itself - NOT the app's own runtime
# requirements (those are declared separately in buildozer.spec's
# `requirements = python3,kivy`).
#
# Install with: pip install -r android/requirements-android.txt
#
# This cannot be installed or exercised on Windows (no WSL/Docker/Android
# SDK on this dev machine) - see android/README.md.
#
# IMPORTANT - keep this in sync with buildozer.spec's `p4a.branch`.
# Buildozer and python-for-android are separate projects that must match:
# buildozer clones p4a itself, so leaving p4a unpinned tracks its master
# branch and silently pairs this buildozer with a bleeding-edge toolchain.
#
# Pinned to buildozer 1.5.0 + p4a v2024.01.21, whose python3 recipe builds
# CPython 3.11.5. Both newer p4a releases (v2026.05.09 and master) build
# CPython 3.14.2, whose venv ships an internally inconsistent pip - its
# build_env/ package is from pip 26.x while exceptions.py is older, so
# every p4a "install pure-python dependencies" step dies with
# "ImportError: cannot import name 'BuildDependencyInstallError'".
# That reproduced on a clean cache with both an old and a matched-pair
# buildozer, so it is a property of the 3.14 toolchain, not of version
# skew or caching. Revisit once p4a ships a 3.14 build with working pip.
buildozer==1.5.0

# Cython must be pinned explicitly: buildozer 1.5.0 does not declare it as
# a dependency (1.6.0 does), it just looks for a `cython` executable on
# PATH and aborts with "Cython (cython) not found" if absent. 0.29.x is
# the series p4a v2024.01.21's recipes are written against; Cython 3.x
# changes default language semantics and is not compatible with them.
cython==0.29.36
